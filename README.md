# 主城排布工具 · 第三版

本机只读游戏存档，在完整主城地图上规划渡劫、研究、操练及其他设施。方案仅用于在游戏中手动摆放，不控制游戏，不写回存档。

## 使用

双击 `启动主城规划器.cmd`，打开 `http://127.0.0.1:18765/`。原 `启动游戏读取服务.cmd` 也可使用。也可以运行 `python -X utf8 server.py`；工具不在游戏目录内时增加 `--game-dir "游戏安装目录"`。

1. 读取存档并核对保存时间。默认只显示已解锁区域，取消“只看解锁区”可恢复完整主城地图。
2. 设置各类设施数量、每座最低工作人员数、各工种总人数和具体人物。初值来自存档，自动识别和能力建议均标注来源，可手动修改。
3. 农田、林地、矿场按工种配置总人数与每人最低主要负责数量。每块有唯一主要负责人；规划会继续争取额外同工种人员也能覆盖，提供可协助范围。
4. 选择自由重排或少搬迁模式，按需锁定建筑；点击开始规划，等待返回已校验的方案。
5. 打开“双图对比”同时查看当前布局和规划布局；关闭后恢复单图切换。两图联动缩放、平移，同一迁移对象使用相同的建／台／设／人编号，点击后同时高亮。迁移清单也显示对应编号，地图不再绘制迁移连线。点击灵台即可查看所放灵物的图片、品质、等级、五行、独立灵气和原存档位置，无需另找列表。

所有主建筑默认可一起重排。自然物与未参与的主城人员保持原位。设施保留所属主建筑，并检查搬迁后的作用范围和总容量。非资源设施的每座最低人数按实际主要工作岗位计算，同一人不会重复计入两座设施的同时工作人数；设为零表示该设施不强制配人。资源主要分工独立，协助关系不重复计数。

## 优化顺序及证明范围

- 优先渡劫台独立灵气；只计算渡劫台中心格，灵物作用范围是曼哈顿三格，保留实际置物台等阶，不虚构升级。
- 默认研究、操练各重点保证一座：先提高两类最佳设施中较低的一项，再提高两项合计。数量为零的工种不参与重点目标。
- 继续提高全部设施对应五行总收益，再争取农田、林地、矿场的额外协助覆盖。
- 少搬迁模式在前置收益条件之后减少迁移与灵物更换。双图中的相同编号表示同一对象，编号不是操作顺序；新增／移除只标在实际存在的一侧。互换位置可能需要游戏中临时腾位。

这一版使用联合几何搜索、灵物唯一分配和固定灵台下的设施／人员细化。只有渡劫灵气达到库存及实际灵台等阶的匹配上界时才显示“渡劫最优已证明”。重点设施、全布局收益和迁移数均需按页面证明状态判断；限时可行结果不等于全局最优。没有找到结果也不等于已证明无解。

研究使用水，操练使用土。环境加成百分比为对应五行值的一半；界面同时展示人物常驻工作能力。临时效果、暴击、科技、目标切换和资源状态影响实际产速，不能把五行值或工作力直接当作每秒产量。源码审查证据见 `GAME_RULES_V3.md`。

## 代码和数据边界

- `game_data.py`、`worker_stats.py`：稳定只读快照、实际游戏属性与人物常驻能力。
- `planning_defaults.py`：明确存档岗位优先，其次使用有标注来源的位置／能力建议。
- `city_planner.py`：第三版规划政策、联合约束搜索、具体灵物分配及迁移差异。
- `city_validation.py`：独立校验实际布局、人数分工、属性和迁移清单。
- `server.py`：本机异步计算任务与只读数据接口，仅监听 `127.0.0.1`。
- `web/`：地图、浮层配置、对象详情和迁移对比。
- `extract_assets.py`：从本机游戏包读取图像到忽略的 `extracted_assets/`；不修改游戏包，不对外发布游戏美术。

旧版清理备份继续保留在上级 `.planner-reset-backups/`，本版不自动读取旧版方案或旧URL中的plan参数。Git历史未改写，不自动提交或推送。

## 开发验证

依赖列于 `requirements.txt`，现有本地 `vendor/` 可复用。运行：

```powershell
python -X utf8 -m unittest discover -p "test_*.py" -v
node --check web/city.js
node --test test_city_ui.cjs
```

真实存档、方案、截图、测试输出、本地图像和安装依赖均不随源码提交。保存的方案带快照日期；游戏继续运行后，应重新读取存档再计算。
