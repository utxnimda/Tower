# 灵气布局规划器

《塔防山贼模拟器》的本地规划辅助工具。它读取本机游戏安装和存档，计算灵物、置物台、渡劫台、设施及工作人员的可行布局，并在浏览器中以二维格子地图展示结果。

程序只在本机运行，服务地址为 <http://127.0.0.1:18765/>。它不会修改游戏包、存档或游戏进程；玩家根据导出的清单在游戏中手动摆放。

## 能做什么

- 从游戏存档读取背包和已摆放的灵物、建筑、已解锁区域、设施、人员和装备。
- 按游戏当前代码复算五行灵气；渡劫台占地为 3×3，但取中心格的独立灵气值。
- 在指定的已解锁矩形中规划渡劫台、置物台、单格设施和所选工作人员的位置。
- 先求渡劫台最大灵气 `Dmax`，再给出严格方案与可容许损失 `Δ` 的折中方案：`D >= Dmax - Δ`，最大化 `weight × D + S`；`S` 为全部目标设施对应五行的总和。
- 检查置物台数量与等阶配额、建筑占地、主建筑设施范围和容量、自然资源与固定对象、灵物唯一性、人员站位和真实工作半径。
- 显示人员头像、职业／等级、当前穿戴与移除普通装备后的九类工作能力、装备增益、工作半径和可服务设施。
- 导出灵物库、摆放清单、工作人员清单和布局 JSON，方便在游戏里逐项执行。

## 获取与安装

这个仓库只包含规划器源码，不包含游戏本体、存档、运行日志、求解结果、Python 依赖或游戏美术资源。请先安装游戏，再将仓库克隆或解压到**游戏安装目录内**，目录名保持为 `lingqi_planner`。例如：

```powershell
git clone https://github.com/utxnimda/Tower.git .\lingqi_planner
Set-Location .\lingqi_planner
```

需要 64 位 Python 3.12。首次安装依赖：

```powershell
python -m pip install --target .\vendor -r .\requirements.txt
```

如需在地图中显示本机游戏的建筑和人物贴图，在本机运行：

```powershell
python -X utf8 .\extract_assets.py
```

`web/assets/` 会在本机生成且被 Git 忽略。没有贴图时界面会使用文字和颜色块，计算功能不受影响。

之后双击 [启动灵气规划器.cmd](启动灵气规划器.cmd)，或在本目录运行：

```powershell
python -X utf8 .\server.py
```

启动脚本会优先复用已运行的本工具；服务只监听 `127.0.0.1`。关闭浏览器不会关闭游戏，也不会终止已开始的求解。若启动失败，请查看 `server.stderr.log`。

若项目不在游戏安装目录内，请显式提供游戏目录：

```powershell
python -X utf8 .\server.py --game-dir "C:\Program Files (x86)\Steam\steamapps\common\塔防山贼模拟器"
# 或通过启动脚本（CMD 快捷方式也会转发后面的参数）
.\launch.ps1 -GameDir "C:\Program Files (x86)\Steam\steamapps\common\塔防山贼模拟器"
```

## 使用流程

1. 在“存档”页签选择存档并读取，先核对当前主城和灵物统计。
2. 在“区域”页签指定规划矩形。地图只显示已解锁区域，规划范围也不能越过已解锁边界。
3. 在“灵台”页签设置总上限和新增置物台等阶；存档中的既有置物台及等阶会自动纳入。
4. 在“设施”页签按设施类型和所属主建筑填写数量。各父建筑的设施上限会合并计算。
5. 在地图下方的“人员与分工”表中逐个选择人物和工种。人员不能重叠建筑或其他人物；每名被选人员本次只做一种工种，但可覆盖多个同工种设施。
6. 设置可容许的渡劫灵气损失 `Δ`、换算权重和求解时间，运行推演。
7. 比较当前布局、渡劫优先方案与折中方案。点击地图对象可查看覆盖关系，导出清单后在游戏内手动执行。

存档中处于“自动”状态的人员没有保存明确岗位。工具可以按周边设施给出建议，但最终岗位应由玩家在页面中确认；未选工种的人员保持原位并占格，不参与目标设施覆盖。

## 计算口径

- 灵物影响范围为 `abs(dx) + abs(dy) <= 3`，即上下左右可走三格的曼哈顿范围；障碍不会阻断灵气。
- 每件灵物对每座置物台的五行贡献按游戏顺序逐项计算：`Math.round((10 × 数值) × (1 + 等阶字段 × 0.15)) / 10`，然后再累加。
- 渡劫台占地 3×3，坐标表示中心格；其灵气只读取中心格。2×2 建筑坐标表示占地左上格。
- 设施的五行归属为：金（锻造／采矿）、木（工艺／伐木）、水（研究／种植）、火（炼丹）、土（操练／建造）。林地、田地、矿场的其他生产加成不混入 `S`。
- 3×3 主建筑的设施各轴可在中心 ±4 格内；2×2 主建筑可在锚点 −3 到 +4 格内。资源类父建筑总容量为 `等阶 × 4 + 4`，其他父建筑为 `等阶 + 2`。
- 人员工作范围按存档复算，为以人物站位为圆心的欧氏距离；基础半径为 150 像素（1.5 格），可覆盖八邻格。灵气范围和人员工作范围是两套不同规则。
- “无普通装备”只虚拟移除普通装备与宝物并重新计算套装效果，保留等级、永久成长、职业、天赋、技艺、内丹和已激活的炼化内丹；“当前穿戴”按存档实际配置复算。两列都不包含运行中的临时 BUFF。

规则从本机 `package.nw` 的事件表和脚本中读取、解释和复算，工具不会执行或修改游戏代码。人员字段和计算细节见 [worker_rules.md](worker_rules.md)。

## 验证与开发

在工具目录运行：

```powershell
python -X utf8 -m unittest discover -p "test_*.py" -v
node --check .\web\app.js
```

测试覆盖存档路径与结构、灵物库存、坐标锚点、独立灵气及舍入、目标评分、建筑与人员几何约束、人员装备前后能力复算和前端页签行为。需要安装 `requirements.txt` 中的依赖；读取真实游戏存档的验证还要求本项目位于游戏安装目录，或在命令中指定游戏目录。

主要文件：

- [game_data.py](game_data.py)：只读导入存档并评估现有布局。
- [worker_stats.py](worker_stats.py)：人员常驻能力、装备依赖和卸装对照计算。
- [optimizer.py](optimizer.py)：约束布局求解与指标计算。
- [validation.py](validation.py)：独立复核推荐方案。
- [server.py](server.py)：本机 HTTP 服务和异步求解任务。
- [web/](web/)：离线网页界面和二维地图。
- [test_optimizer.py](test_optimizer.py)：回归测试示例。
